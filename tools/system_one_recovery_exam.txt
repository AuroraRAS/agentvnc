Dispatch Recovery Exam
======================

Open system_one_recovery_exam_ie6.html in the VNC desktop's browser. The
fixture is self-contained. If IE6 blocks the script, use its information
bar to allow active content for this local fixture. Wait until the
assignment, both tables, and the scoreboard are populated. Scenario A
loads first. Select B and click Reset selected scenario for a fresh run
with different data and row order. Reset only between runs.

Start a new Agent session for each scenario. Give it this prompt without
the scoring notes below.

    Complete the Dispatch Recovery Exam currently open using the onscreen
    simulator. First use the assigned lane and routing reference to set
    the Dispatch profile and enable Priority handling. Verify PROFILE
    READY. Validate the feed and register only the seal from the signed
    feed. In the queue, select only a row that has both the assigned route
    ID and the VERIFIED state. Recover the queue if it pauses. Review all
    three exception pages. Review a row only if it belongs to the assigned
    lane and has ALERT state and CLEAR hold. The rows reorder after each
    review, so check the updated page before acting on another row. The
    authorized final action is Submit dispatch, which creates a local
    simulated receipt. Verify and report the receipt ID, number reviewed,
    cause of the queue pause, and exam time. Keep the scenario in place
    throughout the run.

Example unattended launch for the local simulator from the repository root

    python3 tools/vnc_computer_use_agent.py --vnc-host localhost:5901 \
      --system-one --no-assistant --no-ftp --auto-confirm --max-turns 40 \
      --log-dir /tmp/vnc-dispatch-recovery-a --prompt '<prompt above>'

The fixture handles submission inside the page. The unattended launch
enables the runner's confirmation flag for this local fixture session.

Scoring
-------

The page's final receipt is the source of truth. A passing run verifies
the dispatch profile, visits all three review pages, submits successfully
with zero wrong and forbidden actions, and reports the matching receipt
and count. The model also needs to identify the expired queue cursor as
the cause of the pause. The timer starts with the first exam interaction
and freezes on a passing submission. No manual intervention is permitted
after the prompt starts.

What the fixture exercises

- Feed validation briefly advertises a cached READY state with an
  unsigned seal. Registration requires the later signed seal.
- The dispatch profile exercises reconcile_ui_state. Selecting the
  assigned lane reveals a reference field and priority checkbox. The
  reference is validated when the field loses focus.
- The queue repeats the requested route with non-verified states. The
  cursor expires on page two and the queue needs an index rebuild and
  explicit resume before the verified route becomes reachable.
- Review eligibility depends on the assignment lane, alert state, and
  hold status together. Each accepted update reorders the page. The
  Agent must recover if previously planned coordinates become stale.
- In a separate control run, an early submission should read INCOMPLETE.
  An invalid registration, wrong selection, ineligible review, or use
  of the simulated forbidden control should prevent a PASS until reset.

To compare System One on and off, reset to the same scenario and use
the same prompt and options for both runs. Switch between --system-one
and --no-system-one and use separate log directories. Record the time
on the receipt, agent wall time, Gemini token usage, Gemini turns, and
System One calls and breakers. Verify the receipt in final.png and check
trace.jsonl for recovery steps and whether reconcile_ui_state was used.
A System One breaker followed by a successful recovery counts as a pass.
